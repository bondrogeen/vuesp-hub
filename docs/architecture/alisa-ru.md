# Интеграция с Алисой

Страница `/alisa/` в Vuesp Hub — тестовая интеграция с Яндекс.Станцией через
пакет `alisa-npm`. Hub получает список колонок, подключается к локальным
устройствам и отправляет команды.

## Что нужно

1. Аккаунт Яндекса, к которому привязаны колонки.
2. Зарегистрированное OAuth-приложение Яндекса.
3. `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET` в `.env`.

## Регистрация приложения

1. Откройте <https://oauth.yandex.ru/client/new>.
2. Создайте приложение, например `Vuesp Hub`.
3. Тип — веб-сервис или приложение для доступа к API.
4. В доступах включите `login:info`, `login:email` и, если доступен,
   доступ к устройствам с Алисой / Quasar.
5. Скопируйте **Client ID** и **Client secret** в `.env`:

```env
YANDEX_CLIENT_ID=...
YANDEX_CLIENT_SECRET=...
```

6. Перезапустите hub.

## Важно: парольный вход и модерация

Hub получает токен через `grant_type=password`. Яндекс включает этот grant
только для одобренного приложения. Ответы токен-эндпоинта:

| Ответ | Значение |
| --- | --- |
| `invalid_client` | Client ID/secret не найдены или пара не совпадает |
| `unauthorized_client` | Приложение ждёт модерации, отклонено или заблокировано |
| `unsupported_grant_type` | Для приложения запрещён password grant |
| `invalid_grant` | Client ID/secret верные, но логин или пароль не подошли |

Проверка текущих ключей из `vuesp.ru`:

- `vuesp.ru/.env` → `invalid_client`, пара ключей недействительна;
- `vuesp.ru-backend/.env` → `unauthorized_client`, приложение не прошло
  модерацию для password grant.

Поэтому для теста используйте готовый OAuth-токен: поле **OAuth-токен** на
странице `/alisa/`. Поиск колонок по mDNS работает и без токена.

### Если пароль не подходит

`login or password is not valid` — Яндекс отклонил password grant. Часто это
2FA, капча или вход не в тот аккаунт. В этом случае получите токен через
браузер (implicit flow):

1. Откройте
   <https://oauth.yandex.ru/authorize?response_type=token&client_id=23cabbbdc6cd418abb4b39c32c41195d>
   (эта же ссылка есть на странице `/alisa/`).
2. Войдите в аккаунт, к которому привязаны колонки, и разрешите доступ.
3. После редиректа скопируйте `access_token` из адреса
   `https://music.yandex.ru/#access_token=...&token_type=bearer&expires_in=...`.
4. Вставьте токен в поле **OAuth-токен** и нажмите **Подключить**.

Это тот же клиент, который использует `alisa-npm`, поэтому токен подходит для
`quasar.yandex.net`.

### Временный тестовый режим

Если своего одобренного приложения нет, можно временно включить встроенный
клиент `alisa-npm`:

```env
ALISA_USE_PACKAGE_CLIENT=true
```

Тогда hub использует сторонние `client_id`/`client_secret` пакета только для
получения токена по логину и паролю. Это **только для теста**: для production
нужно своё одобренное OAuth-приложение. Пароль по-прежнему не сохраняется.

## Важно про доступ к колонкам

Публичного OAuth-scope «управление Яндекс.Станцией» может не быть в вашем
приложении. В этом случае вход по логину и паролю вернёт ошибку, а список
колонок не появится.

Рабочие варианты:

- пройти модерацию приложения и включить password grant;
- использовать OAuth-токен, полученный в приложении, которому Яндекс уже
  разрешил доступ к колонкам;
- вставить готовый токен в поле **OAuth-токен** на странице `/alisa/`;
- использовать QR/сессионную авторизацию Yandex Station и передать токен в hub.

Пароль от Яндекса hub не сохраняет: он используется только для запроса токена.
Встроенные `client_id`/`client_secret` пакета `alisa-npm` — сторонние, hub их
не использует.

## Страница

- вход по логину и паролю или готовому токену;
- `Найти колонки` — mDNS-поиск `_yandexio._tcp.local`;
- `Подключить колонки` — локальные WebSocket-подключения;
- карточки колонок: состояние, громкость, play/pause/next/prev, TTS;
- обновление состояния раз в 3 секунды.

## 429 и чужие колонки

`quasar.yandex.net`, `.ru` и `.com` периодически отвечают `429 limited`.
`alisa-npm` падает на `JSON.parse('limited')`, поэтому:

- `scripts/patch-alisa-npm.mjs` (запускается в `postinstall`) меняет host на
  `.ru` и защищает `JSON.parse`;
- hub переопределяет `getDeviceList`/`getAllToken`: перебирает три хоста,
  запоминает рабочий на 60 секунд и не падает на 429;
- если `glagol/token` вернул 404, колонка belongs to another account — она
  пропускается.

Проверено с реальным токеном: 6 cloud-устройств, 3 локальные колонки
подключены, четвёртая чужая пропущена.

## Ограничения текущего прототипа

- токен хранится в памяти процесса и теряется при перезапуске;
- нет OAuth callback и refresh token;
- парольный grant может быть отключён Яндексом — тогда используйте токен;
- доступ к Quasar API зависит от разрешений вашего OAuth-приложения.
